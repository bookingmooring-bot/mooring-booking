## 🗄️ Database Schema (Supabase project: `bblxawscmyzelinidkmb`)

### Tables & key columns

| Table | Description | Key columns |
|---|---|---|
| `profiles` | Extends `auth.users`. Created by trigger on sign-up. | `id (uuid PK = auth.users.id)`, `full_name`, `role (user/provider/admin)`, `subscription_tier`, `ai_questions_used`, `boat_name`, `boat_length`, `address`, `whatsapp`, `provider_consent_at` |
| `moorings` | Core mooring spots. Seeded with 110 Mediterranean entries. | `id (uuid)`, `lat`, `lng`, `country`, `location`, `wind_protection`, `price`, `status (pending/approved/rejected)`, `marketing_tools`, `insurance_mediation` |
| `mooring_availability` | Availability calendar. Composite PK `(mooring_id, date)`. | `mooring_id`, `date`, `is_available`, `custom_price` |
| `bookings` | Reservation records. | `confirmation_code` (auto-generated), `mooring_id`, `check_in`, `check_out`, `guest_email`, `guest_phone`, `status`, `platform_commission (15%, auto-calculated)`, `is_now4today` |
| `reviews` | 1–5 star ratings. Trigger auto-updates avg rating in `moorings`. | `mooring_id`, `rating`, `comment` |
| `commissions` | Provider payout tracking. | `provider_id`, `amount`, `is_paid` |

### ⚠️ Critical DB gotchas
- **IDs are UUIDs** — never use legacy hardcoded IDs like `hr-1`, `gr-2` etc. They break Supabase UUID validation.
- **RLS is enabled** on all tables. Un-authed users can only read `approved` moorings. Providers control their own rows. Admin has full access.
- `profiles` row is auto-created by a trigger on `auth.users` insert. Never manually insert into `profiles` without understanding this trigger.
- `confirmation_code` and `platform_commission` are auto-generated by a trigger on `bookings` insert — don't set them manually.

## 🔍 Debugging Playbook

### Step 1 — Understand the symptom
Ask yourself (or the user): 
- Does it happen only when logged in, or always?
- Is it a build error, runtime crash, or wrong data?
- Does the browser console show an error? A network request failing?
- Is it component-related (render), query-related (data), or auth-related?

### Step 2 — Locate the bug
Use this mental map:

| Symptom | Where to look first |
|---|---|
| White/blank screen | `App.tsx` route config, `main.tsx`, `AuthContext.tsx` |
| "Cannot read properties of undefined" | The component using optional chaining incorrectly, or data not yet loaded |
| Data not loading | Hook file (`useMoorings`, `useBookings`, etc.), Supabase RLS policies |
| Auth not working | `AuthContext.tsx`, `ProtectedRoute.tsx`, Supabase Auth dashboard |
| Form not submitting | `react-hook-form` setup, `zod` schema mismatch |
| TypeScript error | Type definitions in the hook or component props |
| Admin page not accessible | `AdminRoute.tsx`, `role` check in `AuthContext`, profile `role` value in DB |
| Build failing | Check `tsconfig.app.json`, import paths starting with `@/`, missing types |
| Supabase query returning nothing | RLS policy, wrong `eq()` filter, UUID vs string mismatch |
| Style not applying | TailwindCSS class not in safeList, `cn()` utility misuse, conflicting classes |
| i18n key missing | Check `src/i18n/` translation JSON files |
| Weather component broken | `weatherService.ts`, Windy API key in `.env`, `VITE_WINDY_API_KEY` |

### Step 3 — Apply the fix
- Make **minimal, targeted changes** — change only what is causing the bug.
- Respect existing patterns: hooks use React Query, UI uses shadcn/ui components, auth goes through `AuthContext`.
- Do not break RLS by bypassing it; fix the query or add proper `select()` filters instead.
- Keep TypeScript strict — no `any` casts unless absolutely necessary.
- After fixing, explain what was wrong and why your fix resolves it.

## 🚦 Common Bug Patterns & Quick Fixes

### 1. Supabase returns empty array (no data)
**Cause:** RLS policy blocks unauthenticated user, or wrong filter.  
**Fix:** Check if user is logged in. Verify `status = 'approved'` filter on `moorings`. Test query in Supabase SQL editor with `set role anon;`.

### 2. UUID error: `invalid input syntax for type uuid`
**Cause:** Old hardcoded string IDs like `'hr-1'` passed to Supabase.  
**Fix:** Replace with a real UUID from the database. Never use the legacy `src/data/moorings.ts` data file for IDs.

### 3. White screen after navigation
**Cause:** Unprotected route trying to render before auth loads, or missing `ProtectedRoute`.  
**Fix:** Wrap with `<ProtectedRoute>` in `App.tsx`. Add a loading state in `AuthContext` while session initialises.

### 4. React Query stale data / not refreshing
**Cause:** `staleTime` set too high, or `queryKey` not including the right dependency.  
**Fix:** Call `queryClient.invalidateQueries({ queryKey: ['moorings'] })` after a mutation. Check `queryKey` arrays in hooks.

### 5. TypeScript build error on shadcn component
**Cause:** Wrong prop type, missing import, or version mismatch in Radix UI.  
**Fix:** Check the exact component API in `src/components/ui/`. Use `cn()` from `@/lib/utils` for conditional classes.

### 6. Auth context `user` is null on first render
**Cause:** Async Supabase session load. Auth state is not synchronous.  
**Fix:** Always check `isLoading` from `AuthContext` before rendering protected content. Use `ProtectedRoute` which already handles this.

### 7. i18n key showing as raw key string
**Cause:** Key missing from translation file, or wrong namespace.  
**Fix:** Find the file in `src/i18n/` and add the missing key to all language files.

### 8. `npm run build` TypeScript errors
**Cause:** Strict mode catches type errors that `dev` mode ignores.  
**Fix:** Check `tsconfig.app.json` — don't disable strict mode. Fix the types properly: add proper interfaces, use optional chaining `?.`, and null checks.
